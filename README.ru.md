## 1. Введение

Shafile — инструмент для обмена файлами и текстом со сквозным шифрованием. Содержимое шифруется в браузере, а сервер хранит только шифротекст. Поддерживаются лимиты просмотров, запланированное начало и окончание, доступ по паролю и удаление после прочтения.

## 2. Установка и использование

### Требования

- Node.js 24+ (проверено на Node 26)
- pnpm
- HTTPS в производственной среде

### Локальный запуск

```bash
pnpm install
pnpm dev
```

Откройте <http://localhost:3000>. При первом запуске создаются:

- `data/shafile.db`: метаданные SQLite
- `data/blobs/`: хранилище шифротекста
- `data/.secrets.json`: секреты подписи для разработки

### Как пользоваться

1. На главной странице выберите **Создать**, введите текст или выберите файл.
2. Настройте доступ, время начала и окончания, а также лимит просмотров.
3. Создайте ссылку и скопируйте её. В режиме с паролем передайте пароль по другому каналу.
4. Получатель открывает ссылку в браузере, расшифровывает и просматривает или скачивает содержимое.

### Производственное развёртывание

```bash
pnpm build
pnpm start
```

Поставьте обратный прокси Caddy или Nginx перед `127.0.0.1:3000` и включите HTTPS:

```caddyfile
shafile.example.com {
  reverse_proxy 127.0.0.1:3000
}
```

В производственной среде явно задайте `TICKET_SECRET` и `IP_HASH_SECRET`, а при работе за прокси установите `TRUST_PROXY=true`. Перед резервным копированием `data/` остановите сервис. Приложение рассчитано на один экземпляр (SQLite, ограничения в памяти и учёт активных загрузок).

### Docker

В репозитории есть многоступенчатый `Dockerfile` и `docker-compose.yml`.

```bash
docker compose up --build -d
```

Приложение доступно по адресу `http://localhost:3000`. Данные сохраняются в томе `shafile-data`. В производственной среде явно задайте `TICKET_SECRET` и `IP_HASH_SECRET`, при необходимости измените лимиты и `TRUST_PROXY`. Образ использует standalone-сборку Next.js и содержит проверку `/api/health`.

### CI

GitHub Actions (`.github/workflows/ci.yml`) запускает lint, проверку типов, проверку i18n, модульные тесты, production-сборку, Playwright E2E и сборку Docker-образа.

### Переменные окружения

| Переменная | По умолчанию | Описание |
| --- | --- | --- |
| `SHAFILE_DATA_DIR` | `./data` | Корневой каталог данных |
| `DATABASE_PATH` | `$DATA_DIR/shafile.db` | Путь к SQLite |
| `BLOB_DIR` | `$DATA_DIR/blobs` | Каталог шифротекста |
| `TICKET_SECRET` | генерируется | HMAC-секрет токенов доступа |
| `IP_HASH_SECRET` | генерируется | Секрет хеширования IP для лимитов |
| `MAX_SHARE_BYTES` | 5 GiB | Лимит на файл |
| `MAX_STORAGE_BYTES` | 50 GiB | Общий лимит хранилища |
| `TRUST_PROXY` | `false` | `true` при работе за прокси |

### Команды

```bash
pnpm dev          # Сервер разработки
pnpm build        # Сборка для продакшена
pnpm start        # Продакшен-сервер
pnpm lint         # ESLint
pnpm typecheck    # TypeScript
pnpm test         # Модульные тесты
pnpm test:e2e     # E2E-тесты Playwright
pnpm i18n:check   # Проверка ключей и подстановок сообщений
```

Для первого запуска Playwright нужен `pnpm exec playwright install chromium`. Потоковое скачивание больших файлов лучше всего работает в Chromium-браузерах (Chrome, Edge). В остальных браузерах используется расшифровка в памяти с лимитом 256 MiB.

## 3. Раскрытие сведений о шифровании

### Область применения

Shafile шифрует содержимое файлов и заметок в браузере до загрузки. Сервер хранит только шифротекст, зашифрованные метаданные и минимум операционных метаданных, необходимых для применения правил доступа.

### Криптографические примитивы

- **Шифрование содержимого**: AES-256-GCM через Web Crypto API.
- **KDF для пароля**: Argon2id, 64 MiB памяти, 3 итерации, 1 поток, 32-байтный результат.
- **Вывод ключей**: HKDF-SHA-256 с разделением доменов (`shafile/v1/wrap`, `shafile/v1/auth`).
- **Целостность**: теги аутентификации AES-GCM и SHA-256 от открытого manifest.

### Управление ключами

- **Режим ссылки**: случайный 32-байтный ключ содержимого кодируется во фрагменте URL (`/s/{id}#k=...`). Фрагменты не отправляются на сервер.
- **Режим пароля**: ключ содержимого оборачивается ключом, производным от пароля. Сервер хранит только salt, обёрнутый ключ, nonce, параметры KDF и верификатор ключа аутентификации. Пароль и ключ содержимого на сервер не попадают.
- Из пароля выводятся два значения с разделением доменов: `authKey` для авторизации и `wrapKey` для разворачивания. Знание `authKey` не позволяет расшифровать содержимое.

### Формат файла

```
header   = "SHF1" | chunkSize(u32) | noncePrefix(8B) | fileId(16B)
part[i]  = len(u32) | AES-GCM(plaintextChunk_i)
manifest = len(u32) | AES-GCM(JSON{name,mime,size,sha256,chunkCount})
```

Nonce каждого блока — `noncePrefix || u32be(index)`. AAD привязывает хеш заголовка, идентификатор ссылки, номер блока и флаг последнего блока. Имя файла, MIME-тип, размер, SHA-256 и число блоков хранятся в зашифрованном manifest. Текст использует одну запись AES-GCM с тем же ключом содержимого.

### Контроль доступа и видимость на сервере

Сервер видит размер шифротекста, время создания и доступа, число обращений, временное окно, наличие пароля и лимит просмотров. Он не видит имена файлов, содержимое, пароли и ключи. Время начала, окончания и лимит просмотров применяются атомарно; при исчерпании, отзыве или истечении срока шифротекст удаляется.

### Границы безопасности

- Получатель может копировать, делать скриншоты или пересылать расшифрованное содержимое. Это не DRM.
- Ключ ссылки может утечь через историю браузера, буфер обмена, QR-коды, скриншоты или логи на стороне получателя.
- XSS или вредоносное расширение браузера может прочитать расшифрованное содержимое. Проект снижает риск с помощью CSP, отсутствия сторонних скриптов и строгой очистки Markdown.
- Скомпрометированный сервер может отдавать изменённый клиентский код; это фундаментальное ограничение сквозного шифрования, доставляемого через Web.
- Независимый аудит безопасности не заявлен.
