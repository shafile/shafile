## 1. المقدمة

Shafile أداة لمشاركة الملفات والنصوص بتشفير من طرف إلى طرف. يُشفَّر المحتوى داخل المتصفح، ولا يخزّن الخادم سوى النص المشفّر. تدعم حدود المشاهدات، والبدء والانتهاء المجدولين، والوصول بكلمة مرور، والحذف بعد القراءة.

## 2. التثبيت والاستخدام

### المتطلبات

- Node.js 24 أو أحدث (تم الاختبار على Node 26)
- pnpm
- HTTPS في بيئة الإنتاج

### التشغيل المحلي

```bash
pnpm install
pnpm dev
```

افتح <http://localhost:3000>. عند أول تشغيل تُنشأ:

- `data/shafile.db`: بيانات SQLite الوصفية
- `data/blobs/`: تخزين النص المشفّر
- `data/.secrets.json`: أسرار التوقيع للتطوير

### طريقة الاستخدام

1. من الصفحة الرئيسية اختر **إنشاء** وأدخل نصًا أو حدّد ملفًا.
2. اضبط طريقة الوصول ووقت البدء والانتهاء وحدود المشاهدات.
3. أنشئ المشاركة وانسخ الرابط. في وضع كلمة المرور، أرسل كلمة المرور عبر قناة أخرى.
4. يفتح المستلم الرابط في المتصفح لفك التشفير والعرض أو التنزيل.

### النشر للإنتاج

```bash
pnpm build
pnpm start
```

ضع وكيلًا عكسيًا مثل Caddy أو Nginx أمام `127.0.0.1:3000` وفعّل HTTPS:

```caddyfile
shafile.example.com {
  reverse_proxy 127.0.0.1:3000
}
```

عيّن `TICKET_SECRET` و`IP_HASH_SECRET` صراحةً في الإنتاج، واضبط `TRUST_PROXY=true` عند العمل خلف وكيل. أوقف الخدمة قبل نسخ `data/` احتياطيًا. التطبيق حاليًا أحادي المثيل (SQLite وتحديد المعدل في الذاكرة وتتبع التنزيلات النشطة).

### Docker

يتضمن المستودع `Dockerfile` متعدد المراحل و`docker-compose.yml`.

```bash
docker compose up --build -d
```

التطبيق متاح على `http://localhost:3000`. تُحفظ البيانات في وحدة التخزين `shafile-data`. عيّن `TICKET_SECRET` و`IP_HASH_SECRET` صراحةً في الإنتاج، واضبط الحدود و`TRUST_PROXY` حسب الحاجة. تستخدم الصورة مخرجات Next.js standalone وتوفر فحص صحة `/api/health`.

### التكامل المستمر

يشغّل GitHub Actions (`.github/workflows/ci.yml`) فحص lint والأنواع وi18n واختبارات الوحدة وبناء الإنتاج واختبارات Playwright E2E وبناء صورة Docker.

### Cloudflare

يوجد مساران للنشر.

- [Cloudflare Tunnel](docs/cloudflare.md): يحافظ على Node.js وSQLite والقرص المحلي والبث والتنظيف.
- [Workers + D1 + R2](docs/cloudflare-workers.md): بلا خادم بالكامل على Cloudflare، لكنه يخضع لحصص Workers وD1 وR2.

### متغيرات البيئة

| المتغير | القيمة الافتراضية | الوصف |
| --- | --- | --- |
| `SHAFILE_DATA_DIR` | `./data` | جذر البيانات |
| `DATABASE_PATH` | `$DATA_DIR/shafile.db` | مسار SQLite |
| `BLOB_DIR` | `$DATA_DIR/blobs` | دليل النص المشفّر |
| `TICKET_SECRET` | يُنشأ تلقائيًا | سر HMAC لرموز الوصول |
| `IP_HASH_SECRET` | يُنشأ تلقائيًا | سر تجزئة IP لتحديد المعدل |
| `MAX_SHARE_BYTES` | 5 GiB | الحد الأقصى للملف |
| `MAX_STORAGE_BYTES` | 50 GiB | حد التخزين الكلي |
| `TRUST_PROXY` | `false` | اضبطه على `true` خلف وكيل عكسي |
| `CRON_SECRET` | — | سر Cloudflare لتنظيف داخلي |

### الأوامر

```bash
pnpm dev          # خادم التطوير
pnpm build        # بناء الإنتاج
pnpm start        # خادم الإنتاج
pnpm lint         # ESLint
pnpm typecheck    # TypeScript
pnpm test         # اختبارات الوحدات
pnpm test:e2e     # اختبارات Playwright الشاملة
pnpm i18n:check   # التحقق من مفاتيح الرسائل والعناصر النائبة
pnpm cf:build     # Cloudflare Worker build
pnpm cf:preview   # Local D1/R2 preview
pnpm cf:deploy    # Deploy Worker
```

يتطلب Playwright في أول استخدام الأمر `pnpm exec playwright install chromium`. أفضل تجربة لتنزيل الملفات الكبيرة عبر البث في متصفحات Chromium مثل Chrome وEdge. تعود المتصفحات الأخرى إلى فك التشفير في الذاكرة بحد 256 MiB.

## 3. الإفصاح عن التشفير

### النطاق

يشفّر Shafile محتوى الملفات والملاحظات داخل المتصفح قبل الرفع. لا يخزّن الخادم سوى النص المشفّر والبيانات الوصفية المشفّرة والحد الأدنى من البيانات التشغيلية اللازمة لتطبيق قواعد الوصول.

### البدائيات التشفيرية

- **تشفير المحتوى**: AES-256-GCM عبر Web Crypto API.
- **دالة اشتقاق كلمة المرور**: Argon2id بذاكرة 64 MiB و3 تكرارات ومسار واحد وإخراج 32 بايت.
- **اشتقاق المفاتيح**: HKDF-SHA-256 مع فصل النطاقات (`shafile/v1/wrap` و`shafile/v1/auth`).
- **السلامة**: وسوم مصادقة AES-GCM وSHA-256 على manifest غير المشفّر.

### إدارة المفاتيح

- **وضع الرابط**: يُرمَّز مفتاح محتوى عشوائي بطول 32 بايت في جزء URL (`/s/{id}#k=...`). لا تُرسَل الأجزاء بعد `#` إلى الخادم.
- **وضع كلمة المرور**: يُلفّ مفتاح المحتوى بمفتاح مشتق من كلمة المرور. لا يخزّن الخادم سوى الملح والمفتاح الملفوف وnonce ومعاملات KDF ومدقق مفتاح المصادقة؛ ولا يتلقى كلمة المرور أو مفتاح المحتوى.
- تشتق كلمة المرور قيمتين منفصلتين حسب النطاق: `authKey` للتفويض و`wrapKey` لفك اللف. معرفة `authKey` لا تسمح بفك تشفير المحتوى.

### تنسيق الملف

```
header   = "SHF1" | chunkSize(u32) | noncePrefix(8B) | fileId(16B)
part[i]  = len(u32) | AES-GCM(plaintextChunk_i)
manifest = len(u32) | AES-GCM(JSON{name,mime,size,sha256,chunkCount})
```

nonce لكل جزء هو `noncePrefix || u32be(index)`. يربط AAD تجزئة الترويسة ومعرّف المشاركة ورقم الجزء وعلامة الجزء الأخير. يُخزَّن اسم الملف ونوع MIME والحجم وSHA-256 وعدد الأجزاء في manifest مشفّر. يستخدم النص سجل AES-GCM واحدًا بالمفتاح نفسه.

### فرض الوصول وما يراه الخادم

يستطيع الخادم رؤية حجم النص المشفّر وأوقات الإنشاء والوصول وعدد مرات الوصول والنطاق الزمني ووجود كلمة مرور وحد المشاهدات. لا يستطيع رؤية أسماء الملفات أو المحتوى أو كلمات المرور أو المفاتيح. تُطبَّق أوقات البدء والانتهاء وحدود المشاهدات بشكل ذرّي، ويُحذف النص المشفّر عند استهلاك المشاركة أو إلغائها أو انتهائها.

### حدود الأمان

- يمكن للمستلم نسخ المحتوى المفكوك أو التقاطه أو إعادة توجيهه. هذا ليس DRM.
- قد يتسرّب مفتاح الرابط عبر سجل المتصفح أو الحافظة أو رموز QR أو لقطات الشاشة أو سجلات جهة الاستلام.
- يمكن لهجمات XSS أو إضافة متصفح خبيثة قراءة المحتوى المفكوك. يقلل المشروع من ذلك عبر CSP وعدم استخدام سكربتات خارجية والتعقيم الصارم لـMarkdown.
- يمكن لخادم مخترق تقديم تعليمات برمجية معدّلة للعميل؛ وهذا قيد جوهري في التشفير من طرف إلى طرف المقدَّم عبر الويب.
- لا ندّعي إجراء تدقيق أمني مستقل.
